# 阅读稿质量审查

审查由当前 agent 自行完成；不宣称独立专家背书。分别检查事实、编辑价值与阅读负担，任何一项不能由其他项的高分抵消。

## 1. 忠实且有取舍

- 默认顺序是论文信息 → 英文原文 Abstract → Method → Experiment → Discussion → 必要补充。无实验等合理例外说明对应关系。
- 英文摘要保持原文、默认展开且没有中文译文。作者、单位、发表与资源链接有来源，版本不混用。
- 从 `coverage.json` 检查核心贡献、主要实验族、重要反例和限制都有落点。合并次要小节是合理取舍；删掉会改变结论的事实不是精简。
- 核对核心主张、公式、关键数字、图号和实验条件。不能由最终模型更好直接推出某模块有效；区分作者报告与本页分析。
- 原文未披露的信息允许明确缺口，不能补造；判断它是否妨碍核心理解，不扩展成无止境的代码审计。

## 2. 提炼与讨论是否有价值

先暂时跳过原文 Abstract，看剩余正文是否提供这些内容：

| 检查 | 合格表现 |
|---|---|
| 提要 | Method 开头很快说清瓶颈与关键改动；读者知道为何要读后面的机制 |
| 精炼 | 相同信息只解释一次；合并回答同一问题的实验；每段有必要的解释或判断 |
| 方法 | 能从输入追踪到输出，知道继承与创新、关键符号和训练/推理角色 |
| 证据 | 少量有条件的数值对比，解释支持什么、不能支持什么，而非整表复述 |
| 讨论 | 至少两个具体判断，涉及证据强弱、代价、假设或适用边界，并有依据 |
| 图表 | 每张图有阅读任务与结论，原图清楚、出处准确，正文不重复抄图注 |

抽看 Method、Experiment、Discussion 各一段，记录其新增的理解价值。若只是原句翻译、章节重述、没有条件的“更快更准”，就重写。讨论中的“可能”也必须有前提，不能用没有依据的猜测填充批判性分析。

删除测试：删掉某段或某图，如果不影响对机制、证据或边界的理解，也没有独立学习价值，就删去或并入一句。不得删掉关键定义、负面结果或比较条件来换取更短篇幅。

## 3. 10 分钟验收

运行 `scripts/reading_budget.py page.html` 或结构验证器。默认上限 10 分钟，写作目标 8–9 分钟。计入英文 Abstract、正文、图注、表格、公式和所有折叠答案；不能用折叠、缩小字体、超长图片或只给“快速路线”规避预算。

估算是编辑用启发式，不是实测阅读速度。对密集表格、多面板图、陌生推导，人工向上补充 `reading.extra_minutes`，并写清理由；不得调快默认速率来通过。每个补充 HTML 单独验收；主页面须自行讲清核心链条，不能把必读内容移走后声称完成。

超时处理顺序：删重复 → 合并同类证据 → 减少不影响判断的参数/背景 → 必要长推导另成独立专题。核心条件和讨论保留。仍需长篇时，只有用户明确要求才提高预算。

## 4. 闭卷与实际阅读

只用 HTML 回答六个问题，再与原文核对：

1. 论文解决的具体问题与瓶颈是什么？
2. 与最近基线相比真正新增什么？
3. 输入如何经过关键步骤变成输出？核心量意味着什么？
4. 哪组证据最能支持核心贡献，哪些比较不能归因？
5. 提升依赖哪些输入、数据、计算或后处理条件？
6. 什么时候值得使用，什么时候不适合；证据还缺什么？

将答案与正文锚点写入审查记录，不默认全部展示在网页。发现理解断点先修正文，不能仅加外链。完整证明与逐参数复现不作为默认短页考题。

桌面与手机实际查看：章节是否过碎、是否连续可读、图表能否辨认和放大、锚点与键盘是否可用、长公式是否溢出、断网和关闭 JavaScript 后正文是否正常。小字和紧行距不能补救冗长。

## 常见伪完成

- 各原小节都有翻译，却没有取舍、解释或讨论。
- 只有几条亮点，关键机制、证据条件和负面结果被压没。
- 英文摘要后紧接一份含义重复的中文摘要。
- Discussion 只有“效果显著、未来可扩展”，或凭空宣称某应用可用。
- 用全部排行榜截图代替证据分析，把几千字附录藏进 details。
- 手填“10 min”、降低图表阅读成本、提高阅读速率或只统计折叠前正文。
- 估算通过便宣称读者已经全面掌握论文或完成复现。

## 审查记录

输出目录保存 `review.json`：source/version、实际审查范围、事实发现与修正、取舍理由、三段提炼检查、两个讨论判断的依据、六个闭卷问答与锚点、剩余缺口、阅读估算及人工增加时间、静态与浏览器结果。未执行的项保持 not-run。记录覆盖与质量判断即可，不虚构“掌握率”或真人阅读计时。
